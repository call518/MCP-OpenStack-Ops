# MCP-OpenStack-Ops 테스트 및 검증 결과 보고서

## 1. 검증 개요

이 보고서는 현재 MCP-OpenStack-Ops 작업 트리를 Kolla OpenStack 2025.1
테스트 클라우드에서 실제로 검증한 결과를 기록한다.

### 1.1 테스트 목적

이 테스트의 주된 목적은 이슈 #73에서 제안된 다중 사용자 연결 개선이 실제
OpenStack 환경과 Claude Code에서 안전하고 일관되게 동작하는지 확인하는
것이다. 특히 다음 사항을 검증한다.

1. 각 일반 사용자의 요청이 해당 사용자의 Keystone 권한과 프로젝트 범위로
   실행되는지 확인한다.
2. 동시에 여러 사용자가 접속해도 다른 프로젝트의 자원이 노출되거나
   변경되지 않는지 확인한다.
3. 기존 단일 사용자 기능과 등록된 MCP 도구에 회귀 문제가 없는지 확인한다.
4. `prompt_template.md`의 자연어 예제가 실제 Claude Code에서 적절한 MCP
   도구 호출로 연결되는지 확인한다.
5. API 요청 수락뿐 아니라 VM, 볼륨, 스냅샷 등 비동기 자원의 최종 상태까지
   확인한다.
6. 테스트 클라우드의 서비스 부재, 현재 미지원 기능 및 클라이언트 권한 제한을
   애플리케이션 결함과 구분한다.
7. 검증 후 생성한 테스트 자원을 모두 제거해 기존 클라우드 자원에 영향을
   남기지 않는지 확인한다.

## 6. 발견하고 재검증한 결함

### 6.1 스냅샷 작업 후 상태

`set_snapshot`이 실제 스냅샷 생성에 성공했지만 다음과 같이 보고했다.

```text
Post-Action Status: Unknown Resource Type
```

공통 작업 후 상태 조회 함수가 `snapshot` 자원 유형을 처리하지 않는 것이
원인이었다. 스냅샷 조회 경로와 회귀 테스트를 추가했다. 이후 실제 MCP
검사에서 다음을 확인했다.

- `Unknown Resource Type` 결과가 더 이상 발생하지 않음
- OpenStack 스냅샷 최종 상태 `available`
- 스냅샷, 볼륨 및 격리 테스트 프로젝트 삭제 성공

### 6.2 Heat 프로젝트 소유권

일부 Heat 응답에는 명시적인 `project_id`가 없다. 이를 현재 프로젝트로
간주하면 다른 프로젝트 스택이 노출될 수 있었다. 현재 소유권 검사는 명시적인
프로젝트 ID가 일치하거나 Heat self link의 프로젝트 ID가 일치할 때만
허용한다. 소유권을 확인할 수 없거나 서로 충돌하면 거부한다.

실환경 검사에서 자체 프로젝트 스택은 계속 정상적으로 사용할 수 있었으며,
다른 프로젝트 스택은 목록에서 제외되고 상세 조회와 삭제가 거부됐다.

## 9. 결론

검증한 OpenStack 서비스 범위에서 다중 사용자 기능의 핵심 목표가 동작한다.

1. 일반 사용자는 자신의 프로젝트 범위로 제한된다.
2. 다른 프로젝트의 Compute, Network, Storage 및 Heat 자원은 노출되거나
   변경되지 않는다.
3. 관리자와 일반 사용자의 동작 범위가 구분된다.
4. 실제 Claude Code MCP 호출이 실제 OpenStack 클라우드에서 동작한다.
5. 주요 VM, 네트워크, Floating IP, 볼륨, 스냅샷, 백업 및 Heat 경로가
   성공적으로 완료됐다.
6. 비동기 작업은 API 요청 수락을 완료로 간주하지 않고 최종 자원 상태로
   확인했다.
7. 검증 완료 후 모든 격리 테스트 자원을 제거했다.

남은 제한은 주로 테스트 클라우드에 없는 선택적 서비스 또는 확장 기능에서
발생한다. 해당 항목은 Octavia, Aodh, Neutron QoS, Floating IP Port
Forwarding, 시계열 메트릭 백엔드 및 중앙 로그 백엔드다.
